# Coopanion v0.12.0

**新表情和动作（抬头、打喷嚏、灵魂出窍、双手捂脸、摸摸头、抹眼泪等）、说话声、Cortico 0.2.9：一批安全修复、主循环停住后自动恢复、用量页改版和实时汇率**

## 重要修复

- **只收流式请求的服务连不上**：桌宠没连上时（比如刚启动、窗口还没开好），Coo 的请求以前会变成非流式；「测试连接」也一直发非流式请求。只接受流式请求的服务会直接拒绝。现在 Coo 的请求和「测试连接」一律流式。（来自上游 v0.2.13）
- **扩展目录的 `package.json` 带 BOM 时 Core 起不来**：用 Windows PowerShell 改写过的 `extensions/package.json` 开头有 BOM，以前 Core 每次启动都报错退出；现在照常读，读不了时错误里写出文件路径。
- **连接的配置文件带 BOM 时 Core 起不来**：用 Windows 记事本或 PowerShell 存过的连接 `config.json` 开头有 BOM 时，启动时迁移旧连接那一步以前会报错退出；现在照常读。文件内容本身写坏了（不是合法的 JSON）时仍然起不来，请改好或删掉那个连接的文件夹。
- **覆盖安装时提示 Coopanion 还开着**：全局开了 Git 的 `core.fsmonitor` 时，Coo 的工作区每次调用 Git 都会留下一个常驻的 fsmonitor 进程，安装程序把它当成应用还在运行；现在工作区的 Git 调用关掉 fsmonitor。（上游 #338）
- **桌宠起不来时 Coo 整个起不来**：桌宠要用的端口（7797 起的 10 个）都被占时，以前 Core 带着它一起退出，应用重启 5 次后说启动失败；现在只有桌宠不启动，其余照常运行，高级模式的「World 总览」里写出原因，下次启动再试。桌面上这时没有 Coo，应用还不会另外提示（「开始」页显示「没有显示」）。
- **服务拒绝请求时说不清原因**：服务在流里发来错误事件时，以前当成流中断重试 4 次，报的是 `Event before response.created`；现在不重试，错误里带上服务自己的说明，不截断。
- **一轮结束后一直「忙」、消息卡在排队中**：Windows 上杀毒软件、同步盘会在文件刚写完时短暂占用它，Coo 落盘遇到这种情况时，内核会停在处理中，只能重开应用。现在遇到占用会短暂重试；内核万一因为别的错误停下，会自动重启（5 分钟内最多 5 次），重启后补发还没送达的消息。
- **Windows 上选文件夹按钮无效**：选好文件夹后路径框不变的问题已修复。扩展页的「从本机目录安装」和配置里选路径的按钮都受影响。
- **用量记录很大时用量页报错**：用量账本改为分块读取，超过约 512 MB 也能打开。
- **ChatGPT 套餐把可选参数当成必填**（测试中）：经 ChatGPT 套餐调用工具时，没标明严格模式的工具按非严格发，可选参数不再被当成必填，Coo 不会再给它们填占位值。
- **存图失败**：Coo 只给出哈希、没带 `log:` 前缀时，`save_blob` 也能找到要存的图。
- **退出或重启卡住**：Core 12 秒还没停下时强制结束，再等最多 5 秒确认它退出，托盘的「重启」不再因为旧的 Core 没退出而起不来，这样的重启也不算崩溃。打开了使用统计时，退出前最后一次上报最多等 5 秒，统计服务器不响应不会再拖到强制结束；没发出去的留到下次。托盘「显示桌宠」在 Core 不响应时最多等 5 秒。
- **Windows 上选数据文件夹后保存失败没有任何提示**：现在显示文件系统的错误再退出。
- **Windows 上「重启更新」后托盘图标残留**：气泡里的「重启更新」先正常退出（停下 Core、撤掉托盘图标），再安装更新、启动新版。设置窗口的任务栏按钮用程序自己的图标，换目录重装或换了便携版文件夹后不再是空白图标。
- **Windows 上数据在 exFAT、FAT 或网络盘上时装不了扩展**：这类盘建不了 junction，安装版改把 pnpm 的缓存放到 `%LOCALAPPDATA%\Coopanion\pnpm`，扩展按不需要链接的方式安装。便携版的缓存仍放在程序旁边，所以便携版放在这类盘上时装扩展仍可能失败（还没实测）。
- **状态文件写坏后 Core 起不来或少了功能**：这几个文件写坏了（比如断电时只写了一半）时，以前 `notice.json`（接了统计服务器时还有 `telemetry.json`）会让 Core 每次启动都报错退出；`alarms.json` 会让「应用通知」World 整个不可用，Coo 收不到更新说明、设置改动和唤醒器，英文界面下 Coo 也不再按界面语言回复。现在原文件保留为 `.bad`，这一项状态重新开始；`alarms.json` 里只是个别记录不对时只丢那几条。这几个文件改为先写临时文件再整个替换，不会再只写一半。唤醒器到点时保存失败也照样送达，重启后可能再送一次。
- **电脑操作卡住后一直失败**：操作引擎有一次请求超时没回应时，以前之后每次调用都还发给这个卡住的引擎、一直超时；现在超时的引擎会被强制结束，下一次调用换一个新的。被换下的引擎迟到的回应和退出也不会再让新引擎的调用失败。点截图最右下角那一像素时，坐标不会再越过屏幕边缘。
- **关掉语音输入后识别模型还占着内存**：关掉语音输入时，FunASR 模型（几百 MB）当场释放，用的是 Windows 系统识别时它的 PowerShell 进程也会结束；重新打开时再载入。以前只有换引擎时才会停。快速关了又开、或者正在启动时关掉，也不会留下两个识别进程或两份模型。语音输入关着时，「语音输入」页的「启动」按钮是灰的。
- **设置窗口的关机键关掉 Coo 后它又自己回来**：高级模式下左下角的关机键关掉 Core 后，应用以前把这当成崩溃，3 秒后重新启动并弹出崩溃通知。现在关机后 Coo 保持关闭，不重启也不通知；从托盘选「重新启动」或再打开一次程序就回来了。Core 拒绝关机请求时，之后的意外退出仍按崩溃处理。（上游 #456）
- **勾了「接受图片」的连接收不到图**：以前除了勾选，还要这家服务的内置表列明所用模型能看图，图片才发得出去；自己新建的连接（本机模型、别的兼容服务）和表外的模型勾了也收不到图，Coo 操作电脑时看不到截图。现在勾了就发；内置表只决定新建连接、在「开始」页填模型时默认勾不勾。升级后第一次启动时，内置服务地址上勾着「接受图片」、所用模型却不在这家能看图列表里的连接（比如新装时勾着、后来在高级模式换成 `deepseek-v4-pro` 的），会自动去掉勾，这些连接以前本来就收不到图，所以照旧只发文字；自己新建的连接（地址不是内置服务的）和 ChatGPT 套餐的连接不动。只做这一次，之后再勾上就一直勾着。以后换成只能读文字的模型时，请在高级模式「模型」页把「接受图片」去掉，不然带图的请求可能被服务拒绝。（上游 #432）另外，通义千问的 `qwen3.8-max` 也列为能看图：上游的表早就这样列（不是 #432 加的），这里没实测。
- **换了系统默认麦克风后，语音输入还在用原来的设备**：麦克风选的是系统默认时，以前在系统设置里换了默认输入设备（比如插上耳机、换成麦克风阵列），语音输入仍从原来的设备收音，要重启 Coopanion 才换。现在跟着换过去；选了某个麦克风的，保持所选设备。设备被拔掉、音轨断了时也会重新打开麦克风，打不开的（拒绝了麦克风权限除外）在下一次插拔设备时再试。（上游 #455）
- **默认麦克风打不开时换不了别的**：以前设备列表只在麦克风打开成功后才报给「语音输入」页，默认设备打不开时下拉框里只有「系统默认」。现在打开失败时也列出设备，可以换一个再试；没给麦克风权限时读不到设备名，仍不列。（上游 #364）
- **Windows 上鼠标回报率高时桌宠卡顿**：Windows 上桌宠窗口点击穿透时，Electron 为了把鼠标移动转给页面，装了一个全局鼠标钩子，系统里每一次鼠标移动都要经过桌宠窗口的进程，1000 Hz 的鼠标下它会卡住。现在 Windows 上点击穿透时不再转发鼠标移动，改为每 15 ms 查一次光标位置，眼睛跟随、转身和悬停按钮照常；macOS 和 Linux 不变。这一条还没在 Windows 真机上试过。（上游 #465）
- **唤醒器的日期写错时不再顺延**：Coo 设唤醒器时给了不存在的日期（如 2 月 30 日）或超过 23:59 的时间，会被拒绝并让它重写，以前会顺延到下个月。

## 改动

- **连续失败的气泡按错误码给建议**：以前不论什么错误都请你去检查模型名和 API Key，并带「打开设置」。现在 401、403 请检查 API Key，404 请检查模型名，这两类带「打开设置」；429 和 5xx 说是服务那边出了问题或在限流、过会儿再试；其余错误（比如服务商内容审核回的 400、连不上）只说原因，只有「知道了」。（上游 #438）
- **Coo 默认上下文变大**：上下文阶段预算从 64000 提到 128000，交接保留比例从 1/3 改为 0.25，所以 Coo 整理对话（交接）的时机会晚一些。在高级模式「Cormini」页的「上下文与交接」里保存过设置的，保留你的设置。
- **给 Coo 的几处说明文字随 Cortico 变了**：
  - `save_blob` 工具里 `handle` 参数的说明，写明要照抄 `[blob ...]` 行里的 `log:` 句柄，比如 `log:1a2b3c4d`。
  - 交接笔记：合并重复的提示改成「同样的一条共出现 N 次」，「N 条新事件」这类投递计数通知不再写进笔记。
  - 系统前缀里的工作区清单：直属文件超过 10 个的目录折成一行，写明文件数和用 `list_files` 列全的方法。工作区里有文件夹超过 10 个文件后，Coo 的前缀会因此变化一次。
  - 新的文件工具 `move_file`：移动或改名文件和文件夹，也能把一份文件里的几行剪到另一份。常驻前缀的 `CONSTITUTION.md` 不能整份移走或删掉，移走它所在的文件夹时也会留下它。
  - `read_file` 可以只读几行（`offset` / `limit`）；不给时，超过上下文余量的大文件（默认约 19200 字符）只交回开头。
  - `delete_file` 的说明改了；`list_files`、`find_files` 的结果每份文件带上大小和日期。
  - 有 World 启动失败时，Coo 会收到一句「World「X」启动失败,本次运行里没有它」和原因。
- **刚打开电脑操作时，Coo 等工具到位才知道**：「电脑操作已打开」这条设置通知，要等电脑操作真正启动、Coo 的工具里有了它才送出（最多等 40 秒），以免 Coo 听说能用了却还没有工具。
- **Cortico 升到 0.2.9**（`e42d4e44`），和上游 Coopanion v0.2.13 用的是同一版。
- **用量报告改用实时汇率**：打开「用量与成本」页时，Core 向 `open.er-api.com`（失败时换 `latest.currency-api.pages.dev`、`cdn.jsdelivr.net` 上的汇率接口）取汇率，缓存 12 小时，都取不到时用内置汇率。这是新增的对外访问，已写进 README 的「其他联网」。配置里不再有手填汇率 `usage.rates`，`config.json` 里写过的值不再读取，留着无害。
- **加在 Coopanion 上的 Chromium 开关也传给桌宠窗口**：桌宠窗口是单独的进程，以前只带 `--pet-host`，快捷方式上加的 `--disable-gpu-compositing`、`--no-sandbox` 等只对设置窗口有用。现在应用启动参数里以 `--` 开头的都带给它（会占端口的调试开关，以及桌宠窗口自己的 `--pet-url=`、`--parent-pid=` 除外：这两个只由桌宠 World 给）。部分 Windows 电脑上桌宠所在的屏幕整块变黑时，可以在快捷方式「目标」末尾加 ` --disable-gpu-compositing` 试试，README 常见问题里有这一条。（上游 #378）
- **安装包只带中文和英文的 Chromium 语言文件**：Chromium 自身的少量文字（表单提示、右键菜单、文件对话框）只留简体中文、繁体中文和英文，Mac 版装好后的应用因此小了约 48 MB（dmg 压缩后的差别、Windows 和 Linux 包都没量过）。其他系统语言下这些文字显示英文；应用的语言判断不受影响。（上游 #349，上游留了 11 种语言）
- **系统代理按每次请求实时查**：以前每次 Core 启动时查一次，对所有网站用同一个结果；现在按请求的网站去问系统，打开或关掉代理软件不用重启 Coopanion，PAC 脚本也按网站分别生效。启动环境里设了 `HTTP_PROXY` / `HTTPS_PROXY` 时仍以环境变量为准。

## 界面

- **「习惯」页可以给 Coo 改名**：新的「Coo 的名字」一行，改了以后左栏、「开始」页的标题、桌宠菜单、对话页和气泡里的授权提问当场换成新名字，不用重启；清空就回到 Coo。改的是 Core 配置里的 `displayName`，和左栏里直接改名是同一项。Coo 的人设里它仍自称 Coo。
- **设置窗口记住大小**：关掉设置窗口或退出应用时记下窗口大小（非最大化时的），下次按这个大小打开，并收进主屏幕的可用区域；第一次仍是 1180 × 800。记在数据文件夹的 `settings-size.json` 里，便携版在程序旁边的 `data` 里。（上游 #436 的一部分；上游同时改的整条标题栏没有跟）
- **「桌宠窗口」灯只看窗口**：高级模式里桌宠 World 的「桌宠窗口」灯，以前在浏览器里开着 `/pet` 时也亮着「页面已连接」，哪怕桌宠窗口根本没开；现在只有桌宠窗口连着才亮，浏览器页面顶替窗口时只在说明里提一句。窗口里连 Coo 都画不出来（比如显卡给不了 WebGL）时，灯显示出错和原因。（上游 #379）
- **电脑操作的设置没保存上时**，页面显示 Coo 此刻实际用的设置，而不是你刚点的。
- **界面文字里指 Coo 的「它」改成直接写 Coo**：比如电脑操作的风险说明、对话页的步骤名「调整设置」（原「调整自己」），英文界面同样。
- **你说的话改成灰底气泡，叠在 Coo 头顶**：你打的字、说的话和「对话」页发的消息，以前是虚线气泡、放在 Coo 背朝的一侧并有三个小圆点连到 Coo；现在是和「对话」页一样的灰底气泡，居中叠在 Coo 的气泡上方（没有气泡时在头顶），最新的在最下面。
- **「习惯」页加「在 Coo 头顶显示你说的话」开关**（默认开）：关掉后打字和「对话」页发的消息不在头顶留气泡，已留着的立即淡出；说话时照样显示识别到的字，识别完就淡出。
- **「习惯」页加「气泡速度」**：50%–200%，调 Coo 的气泡逐字出现和停留的快慢，`pet_say` 告诉 Coo 的显示时长也按它算（默认 100% 时和以前一样）。只有你能改，Coo 自己改不了。
- **说话声**（默认关，来自上游 v0.2.7）：「习惯」页新增「说话声」一节。打开「念出气泡文字」后，Coo 的气泡每打出一个字，就念一个动森式的短音节，代替「说话」类的叽咕声，换哪个形象都是同一个声音。中文按拼音念，英文查发音词典，一句话里有假名时按日语念。音高、语速各有低、中、高三档，也可以自定义数值。它跟着音效总开关和「说话」类开关走，Coo 隐藏时也不出声。打开后气泡在句末停得更久、字母打得更快，`pet_say` 告诉 Coo 的显示时长也按这个节奏算。音节库和发音词典让安装包大了约 3.5 MB，来源和许可见桌宠包的 `THIRD_PARTY_NOTICES.md`。
- **打字框可以写多行**：随文字长高，最多六行后滚动；Enter 发送，Shift+Enter 换行，输入法选字时按的 Enter 不会把半句话发出去。
- **打字框可以粘贴图片**：最多 4 张，按「对话」页的规则缩小（长边不超过 2048，仍超过 6 MB 时改成 JPEG）；现在的模型看不到图片时，框下提示 Coo 只会知道发了几张。「在对话页继续写」把图片和文字一起带过去，只有图片也行。（上游 #430）
- **打字键**（默认关）：「习惯」页新的「用打字键打开打字框」，打开后在任何窗口里按这个键都能打开桌宠的打字框，默认双击左 Ctrl（Mac 是左 Control）；按键（组合键或鼠标侧键）和按一下还是双击都能改。Mac 上和说话键一样要允许「输入监控」，读不到键时那一行写明原因。（上游 #361）
- **气泡在鼠标停在上面时不收起**：Coo 说话的气泡、引导里不需要回答的一步，鼠标停在上面时倒计时停住，移开后接着走完，排队的下一句也先等着；带链接的气泡也一样。（上游 #430）
- **语音输入可以用 OpenAI 兼容的转写接口**（上游 #380）：「语音输入」页的识别引擎多了「转写接口（OpenAI 兼容）」，填写地址、模型和 API Key 后，每句话说完把这句的录音（16 kHz 单声道 WAV）发给 `{地址}/audio/transcriptions`，收到回应才出字。远程地址只能用 https，本机和局域网的地址可以用 http；Key 存在数据目录的 `.env`（只有你能读），不写进 `config.json`。请求失败时「识别服务」一行和 Coo 身旁的麦克风按钮显示状态码和接口的消息，之后不再发送，直到点「启动」、改了地址或模型、存了新的 Key，或换了界面语言。接口回应跳转（3xx）时也算失败，录音不会跟着发到别的地址（上游会跟过去）。选它以后录音会离开这台电脑；默认仍在本机用 FunASR 识别。

## 安全

- **远程模型地址只能用 https**：http 不加密，API Key 和对话会明文传输。本机和局域网的地址（`localhost`、`192.168.x.x`、`10.x.x.x`、`.local` 名字、Tailscale 地址等）仍然可以用 http；之前存下的 http 远程地址，连接仍在列表里，但请求会在发出前失败，请改成 https 地址。
- **模型请求遇到重定向直接失败**，不再跟到别的地址去，API Key 不会被带去新地址。Gemini 的模型列表和 Anthropic 的请求（含模型列表）也一样；别家的模型列表跨网站重定向时，Key 也不会带过去。服务换了地址的，请在设置里换成新地址。
- **模型列表有上限**：Gemini 的模型列表最多读 20 页、整体 60 秒，翻页令牌重复就停；Anthropic 的模型列表读满 2000 个就停。以前服务一直说「还有下一页」时会无限请求下去。
- **API Key 文件只有你自己能读**：保存 Key 时，连接的 `.env` 先写临时文件再整个替换，权限 0600；新建的连接目录是 0700。已有的 `.env` 要等下次保存 Key 才改权限。复制一个没有密钥变量的连接（比如用 ChatGPT 账号登录的连接）时，不再把令牌文件一起复制。
- **本机网页的来源检查更严**：省略端口的来源按默认端口比较，`http://localhost` 不再被当成设置窗口的端口；只有本机页面能把设置窗口的页面嵌进框里。
- **桌宠本地服务只听自己的页面**：桌宠服务的写请求和 WebSocket 只接受它自己的地址（含端口）。以前本机任意端口上的网页（比如别的开发服务器、包里的网页）都能改桌宠的外观、偏好，导入形象包，甚至冒充桌宠窗口。桌宠窗口现在用启动时拿到的随机凭据连接，被替换后会自己重连。
- **形象包里的网页在沙箱里**：形象包目录下的文件带 `sandbox` 的 CSP 和 `nosniff`，包里的 HTML、SVG 被当成网页单独打开时连不了网络，也调不了桌宠服务。
- **桌宠窗口和装扮窗口不会被带走**：这两个窗口只显示桌宠服务自己的页面，拖进来的链接或页面里的跳转不再离开；外部链接只交给浏览器打开 http(s) 地址，`file:` 和别的协议直接丢弃；窗口进程只接受桌宠窗口自己页面发来的消息。
- **设置窗口只运行 Core 的脚本**：设置窗口里的页面只运行 Coopanion 自己的 Core 提供的脚本（扩展的页面也由它提供），不运行内联脚本和插件。只有设置页本身和桌宠的页面会在应用的窗口里打开，以前本机任意端口上的网页都能开成带设置窗口权限的应用窗口；别的 http、https 链接交给浏览器，`file:` 等其他协议直接丢弃，设置窗口也不会被跳转到别的网站。

## 已知问题

- 设置没保存上（比如数据文件夹没有写入权限）时，Cortico 已经先把新值用上了，Coo 会一直用新值到应用重启，重启后回到 `config.json` 里的旧值。
- 改了某个连接的地址后点「测试」，已存的 Key 仍会发往新地址。只在你自己改地址时发生，上游计划在 Cortico 0.3.0 修复。Coo 连接改成 http 远程地址时会先被拒绝，所以只剩改成别的 https 地址（或本机、局域网地址）这种情况。
